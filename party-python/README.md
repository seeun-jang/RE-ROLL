# 미니게임 파티 — 공통 틀 + 줄다리기 + 손바닥 밀치기 + 음성 퀴즈 + 주문을 외쳐라 + 무궁화

2~5명이 각자 컴퓨터의 브라우저로 접속해 미니게임을 하는 틀이다.
지금은 시험용 대기실과 줄다리기 하나가 들어 있다. 전체 판(보드)은 나중에 만든다.

## 폴더

```
party/
├─ docs/COMMON_SPEC.md      미니게임 공통 규격과 통신 규약
├─ server/                  Python 서버 (FastAPI)
│  ├─ requirements.txt
│  ├─ party/main.py         서버 진입점 (화면 파일 + /api + /ws)
│  ├─ party/hub.py          대기실: 참가자, 게임 시작·종료
│  ├─ party/minigame.py     미니게임 공통 규격(서버 쪽)
│  ├─ party/games/tug/      줄다리기 판정 (박자, 줄, 팀, 점수)
│  ├─ party/games/palm/     손바닥 밀치기 판정
│  ├─ party/games/quiz/     음성 퀴즈 판정 + 문제 은행 + Gemini 문제
│  ├─ party/games/spell/    주문을 외쳐라 판정 (결투 규칙, 주문 글자 판정)
│  ├─ party/games/mugunghwa/ 무궁화 꽃이 피었습니다 판정 (사람 술래, 음성으로 돌아보기)
│  ├─ party/services/       공용 AI 서비스 (음성 인식 Whisper, Gemini)
│  ├─ requirements-ai.txt   음성 인식용 추가 패키지(선택)
│  ├─ tools/check_ai.py     AI 기능 점검
│  └─ tests/                테스트
└─ web/                     화면 (Vite)
   ├─ package.json
   ├─ src/main.js           시험용 대기실
   ├─ src/session/          LocalSession, RemoteSession
   ├─ src/games/registry.js 게임 목록
   └─ src/games/tug/        줄다리기 화면 (원본 + net/, sim/, minigame.js)
```

## 설치 (Windows, 처음 한 번)

필요한 것: Python 3.11 이상, Node.js 22 이상.

`party\server` 폴더에서:

```
python -m pip install -r requirements.txt
```

`party\web` 폴더에서:

```
npm install
```

## 실행

### A. 서버 없이 화면만 확인 (LocalSession)

`party\web` 폴더에서:

```
npm run dev
```

브라우저에서 `http://localhost:5173/?local=3` 을 연다. 숫자는 봇을 포함한 전체 인원(2~5)이다.
화면 위에 "시험용 모드" 띠가 보이면 맞다. 봇과 하는 것이며 서버 판정이 아니다.

### B. 실제 서버로 개발하면서 확인

창 두 개가 필요하다.

1. `party\server` 폴더에서: `python -m uvicorn party.main:app --host 0.0.0.0 --port 8000`
2. `party\web` 폴더에서: `npm run dev`

브라우저에서 `http://localhost:5173/` 을 연다. 탭을 여러 개 열면 탭마다 다른 참가자가 된다.

### C. 빌드해서 주소 하나로 실행

1. `party\web` 폴더에서: `npm run build`
2. `party\server` 폴더에서: `python -m uvicorn party.main:app --host 0.0.0.0 --port 8000`

브라우저에서 `http://localhost:8000/` 을 연다. 다른 컴퓨터는 터널 주소로 접속한다.

### 다른 컴퓨터에서 접속 (Cloudflare Quick Tunnel)

C 방식으로 서버를 켠 뒤, 아무 폴더에서:

```
cloudflared tunnel --url http://localhost:8000
```

출력된 `https://....trycloudflare.com` 주소를 참가자에게 알려 준다.
주소는 실행할 때마다 바뀌고, 서버 PC와 두 프로그램을 계속 켜 두어야 한다.

### 끄기

각 창에서 `Ctrl + C`.

## 줄다리기 규칙 (원본과 달라진 점)

- 각자 자기 컴퓨터에서 **Space** 로 당긴다. `M` 은 소리 끄기/켜기.
- 인원에 따라 팀을 나눈다: 2명 1:1, 3명 1:2, 4명 2:2, 5명 2:3.
- 인원이 적은 팀은 힘에 (많은 팀 인원 ÷ 적은 팀 인원)을 곱한다. 2:3 이면 1.5배(원본과 같음), 1:2 면 2배.
- 일시정지와 건너뛰기는 없다. 장면은 서버가 정한 시각에 모두 함께 넘어간다.
- 점수 기록 화면의 '결과 확인'은 아무나 누를 수 있고, 15초가 지나면 자동으로 넘어간다.
- 3라운드, 라운드마다 팀 재배정, 개인 점수 최고가 승리하는 규칙과 점수 계산은 원본 그대로다.

숫자는 `server/party/games/tug/config.py` 에서 바꾼다. 서버가 이 값을 화면으로 보낸다.

## 손바닥 밀치기 규칙 (원본과 달라진 점)

- CPU 상대를 없애고 사람끼리 겨룬다. 판정·점수·진행은 모두 Python 서버(`server/party/games/palm/`)가 한다.
- 대진: 모두가 서로 한 번씩 만나도록 라운드마다 둘씩 짝지어 **동시에** 대결한다.
  - 2명: 같은 상대와 3판 / 3명: 3라운드 / 4명: 3라운드(2경기씩) / 5명: 5라운드(2경기씩)
  - 인원이 홀수면 라운드마다 한 명이 쉬면서 관전한다(모두 한 번씩 쉰다).
- 최종 순위: 이긴 횟수가 많은 순, 같으면 점수 합이 높은 순. 둘 다 같으면 공동 순위.
- 조작(원본 그대로): A/D 무게중심, J 밀기(길게 누르면 차지), K 손 빼기, L 버티기, M 소리.
- 한 판의 규칙(30초, 균형 게이지, 밀기/차지/손빼기/버티기 상성, 점수 공식)은 원본 값 그대로이다.
- 내 캐릭터는 항상 화면 왼쪽에 보인다.

## 음성 퀴즈 규칙 (원본과 달라진 점)

- 2팀이 한 PC 에서 하던 것을 2~5명이 각자 PC 에서 하도록 바꿨다. 판정·점수·진행은 모두 Python 서버(`server/party/games/quiz/`)가 한다.
- **버저**: 스페이스 키. 누른 시각이 가장 빠른 사람이 답변 기회를 얻는다(통신 지연은 0.35초까지 보정).
  원본의 "팀 이름 외치기 / 손 들기" 버저는 뺐다.
- **답변**: 버저를 잡으면 10초 안에 마이크로 정답을 말한다. 말이 끝나면 소리가 서버로 가고, 서버의 Whisper 모델(Hugging Face)이 글자로 바꿔 판정한다.
  잘못 알아들었을 때를 대비해 2번까지 말할 수 있다. 입력창에 타자로 쳐도 된다(타자는 1번 제출 = 1번 판정).
- **오답·시간 초과**: 그 문제에서 잠기고 -50점. 남은 사람끼리 계속 버저 경쟁을 한다. 모두 틀리면 정답을 공개하고 다음 문제로 간다.
- **정답**: +100점. 문제 10개, 문제당 45초(누군가 답하는 동안에는 멈춤), 10초 뒤 초성 힌트, 20초 뒤 첫 글자 힌트(원본 그대로).
- **최종 순위**: 점수 높은 순 → 정답 많은 순 → 정답까지 걸린 시간 합이 짧은 순.
- **문제**: 서버에 `GEMINI_API_KEY` 가 있으면 Gemini 가 만든 문제를 먼저 쓰고(화면에 "Gemini 출제" 표시), 없거나 모자라면 원본 문제 은행 170개에서 낸다.
  Gemini 가 만든 문제는 은행과 같은 규칙(한글 2~7글자 정답, 문제에 정답 없음 등)으로 검증해 통과한 것만 쓴다.
- 정답은 공개되기 전까지 브라우저로 보내지 않는다.

### 음성 인식 켜기 (Hugging Face Whisper, 서버 PC 에서 실행)

`party\server` 폴더에서(자세한 내용은 `requirements-ai.txt`):

```
python -m pip install torch --index-url https://download.pytorch.org/whl/cu126
python -m pip install -r requirements-ai.txt
python tools\check_ai.py
```

- 처음 실행할 때 모델(약 1.6GB, `openai/whisper-large-v3-turbo`)을 내려받는다. 무료이고 계정이 필요 없다.
- 그래픽카드가 없으면 자동으로 작은 모델(`openai/whisper-small`)을 CPU 로 돌린다. 모델을 바꾸려면 `PARTY_STT_MODEL` 환경 변수.
- 설치하지 않았거나 `PARTY_STT=off` 이면 음성 없이 타자 입력으로만 진행된다.
- 마이크는 브라우저 규칙상 `localhost` 또는 `https` 주소에서만 켜진다. 다른 컴퓨터는 Cloudflare 터널 주소(https)로 들어와야 한다.

### Gemini 문제 생성 켜기

1. https://aistudio.google.com/apikey 에서 API 키를 만든다(무료 등급, 카드 등록 없음).
2. 서버를 켜는 PowerShell 창에서 키를 넣고 서버를 켠다. 키는 파일에 적지 않는다.

```
$env:GEMINI_API_KEY = "여기에_키"
python -m uvicorn party.main:app --host 0.0.0.0 --port 8000
```

- 서버가 켜지면 뒤에서 문제를 미리 만들어 둔다(서버 창에 `[음성 퀴즈] Gemini 문제 N개 준비` 가 나온다).
- 모델 이름은 `GEMINI_MODEL` 환경 변수로 바꿀 수 있다. 비워 두면 `gemini-flash-lite-latest` 등 후보를 차례로 시도한다.
- 상태 확인: 브라우저에서 `http://localhost:8000/api/health` → `"stt": "ready"`, `"gemini": true`.

## 주문을 외쳐라 규칙 (원본과 달라진 점)

- CPU 상대(불꽃 마법사)와 튜토리얼을 없애고 사람끼리 1:1 로 결투한다. 판정·진행은 모두 Python 서버(`server/party/games/spell/`)가 한다.
- 대진: 손바닥 밀치기와 같다. 라운드마다 둘씩 짝지어 **동시에** 결투하고 모두 한 번씩 만난다(2명은 같은 상대와 3판). 홀수면 한 명이 쉬며 관전한다.
- 최종 순위: 이긴 횟수가 많은 순, 같으면 결투가 끝났을 때 남은 체력의 합이 높은 순.
- **주문 입력**: 결투 중에는 마이크가 계속 듣는다. 주문 이름(파이어볼 · 아쿠아 샷 · 썬더 · 윈드 커터 · 아이스 실드 · 힐)을 외치면
  서버의 Whisper 가 글자로 바꾸고, 원본의 주문 판정(자모 단위 유사도)이 어느 주문인지 가린다. "파이어 벌"처럼 조금 다르게 들려도 인정한다.
  주문이 아닌 말은 "???" 와 함께 들린 말을 보여 준다. 숫자키 1~6 과 주문 칸 클릭으로도 쓸 수 있다.
- **위력 고정**: 소리 크기·키를 누르는 시간과 상관없이 항상 원본의 '보통' 위력이다.
- 결투 한 판은 60초(원본 90초). 체력이 0 이 되면 K.O., 시간이 끝나면 남은 체력 비율이 높은 쪽이 이긴다.
- 양쪽 모두 원본의 플레이어와 같은 조건이다(체력 100, 마나 100, 초당 6 회복, 주문 6개의 피해·마나·쿨다운, 콤보 보너스는 원본 값).
- 투사체끼리 만나면 상성(불 → 바람 → 번개 → 물 → 불)으로 상쇄된다. 썬더는 투사체가 아니라 요격할 수 없다.
- 얼음 방패는 투사체와 썬더를 모두 막는다(불 속성에는 1.5배로 깎인다).
- 원본의 적 전용 요소(공격 예고, 화염 방벽, 분노 단계, 속성 친화 배율)는 없다.
- 내 캐릭터는 항상 화면 왼쪽에 보인다.

## 무궁화 꽃이 피었습니다 규칙 (원본과 달라진 점)

- 원본은 술래가 CPU 이고 5명이 키보드 하나로 했다. 이제 **참가자 한 명이 술래**가 되고, 각자 자기 PC 에서 한다.
  판정·진행은 모두 Python 서버(`server/party/games/mugunghwa/`)가 한다.
- **술래**: 서버가 무작위로 한 명을 뽑는다(한 판). 술래가 마이크에 "무궁화 꽃이 피었습니다"를 외치면
  서버의 Whisper 가 글자로 바꿔 문장이 맞는지 확인하고(조금 다르게 들려도 인정), 맞으면 술래가 돌아본다.
  중간에 0.5초 넘게 쉬면 말이 끊긴 것으로 보아 인정되지 않는다(다시 처음부터). 빨리 말하거나 일부러 끊어 속일 수 있다.
- **뒤돌기**: 돌아본 뒤 최소 1초는 지켜보고, 술래가 다시 외치기 시작하면 뒤돈다. 아무 말도 안 해도 4초 뒤에는 뒤돈다.
- **도망자**: 스페이스를 누르고 있으면 전진, 떼면 멈춘다(원본처럼 관성 때문에 바로 멈추지 못한다).
  술래가 돌아보기 시작하고 0.4초(유예)가 지나도 움직이고 있으면 탈락한다.
  다른 사람의 화면에는 술래가 외치는 동안 문구 상자에 글자가 차례로 나타난다(실제 말을 따라가는 것이 아니라 "외치는 중" 표시).
- **승패**: 제한 시간 45초 안에 도망자가 한 명이라도 결승선(15m)에 닿으면 도망자 쪽 승리, 그 자리에서 끝난다.
  아무도 못 닿으면(전원 탈락 또는 시간 종료) 술래 승리.
- **점수**: 이긴 쪽이 항상 진 쪽보다 높다.
  - 도망자 승리: 도착한 사람 1000 / 나머지 도망자 600 + 간 거리 비율×300(탈락자는 탈락 지점까지) / 술래 = 잡은 사람 수×100
  - 술래 승리: 술래 1000 / 도망자 = 간 거리 비율×500
- 음성 인식이 꺼져 있거나 마이크를 못 쓰면, 술래는 스페이스를 1.5초 넘게 눌렀다 떼는 것으로 "외치기"를 대신한다.
- 캐릭터: 도망자는 술래 쪽을 보고 달리므로 동물 캐릭터의 **뒷모습**(얼굴을 털 색으로 덮어 만든 그림)으로 보인다. 술래는 뒤돌아 있을 때 뒷모습, 돌아보면 앞모습.

## 소리 따라하기 규칙 (원본과 달라진 점)

- 소리 3개(쉬움 → 보통 → 어려움, 난이도마다 3개 중 무작위)를 차례로 따라 한다.
- 라운드마다: 제시 소리를 모두에게 2번 들려줌 → **한 명씩 차례로** (원본 1번 더 듣기 → 3·2·1 → 녹음 → 채점 → 공개).
- 공개할 때 그 사람의 **녹음을 모두에게 들려준 뒤** 점수(0~100)와 등급(S 90 / A 75 / B 60 / C)을 보여 준다.
- 차례 순서는 시작할 때 무작위로 정하고, 라운드마다 시작하는 사람이 한 칸씩 밀린다. *(임시로 정한 값)*
- 3라운드 점수 합이 높은 순으로 순위. 동점은 공동 순위.
- 소리가 감지되지 않거나 마이크를 쓸 수 없으면 그 차례는 0점.
- 채점: 서버가 **허깅페이스 Whisper 모델의 인코더**(음성 인식에 쓰는 것과 같은 모델, 추가 다운로드 없음)로 제시 소리와 녹음의 특징을 뽑아 시간축을 맞춰(DTW) 비교한다.
  - 100점 기준 = 제시 소리 자신, 0점 기준 = 다른 제시 소리·잡음과의 유사도. 그 사이를 점수로 바꾼다(`SCORE.GOOD_FRACTION`).
  - Whisper 를 쓸 수 없으면(`PARTY_STT=off` 또는 torch 미설치) numpy 로 만든 간단한 주파수 특징으로 대신 채점한다. 서버 로그에 `채점 준비 완료(whisper)` 또는 `(spectral)` 로 표시된다.
  - 원본은 librosa(음높이·음색·리듬) 채점이었으나 Whisper 인코더 채점으로 바꿨다.
- `?local=N` 시험용 모드는 채점 모델이 없어 점수가 임의 값이다(화면에 표시됨).
- 녹음은 브라우저에서 잡음 제거·자동 음량 조절을 끄고 받는다(휘파람·허밍이 지워지지 않게).
- 수치는 `server/party/games/mimic/config.py` 에 있다.

## 과일자르기 규칙 (원본과 달라진 점)

- 60초 고정. **모두에게 같은 과일**이 각자 화면에 같은 시각·같은 궤적으로 나오고, 점수가 높은 순으로 순위(동점은 공동 순위).
- 베는 방법: **카메라 손 인식**(검지를 빠르게 휘두르기) + **마우스 보조**(왼쪽 버튼을 누른 채 긋기, 터치 가능). 둘을 동시에 쓸 수 있다.
- 과일 10~20점, 3개 이상 연속으로 베면 콤보 보너스(개수 × 5점).
- **폭탄은 20점 감점만**(원본의 하트 3개·GAME OVER 는 없앴다). 0점 아래로는 내려가지 않고, 이어지던 콤보가 끊긴다.
- 황금 별과일: 8초 동안 점수 2배. 프리즘 베리: 벤 사람에게만 과일이 한꺼번에 쏟아지고 6초 동안 과일이 3배로 나온다(추가 과일도 미리 정해져 있어, 벤 사람끼리는 같은 과일을 받는다).
- 판정: 브라우저는 칼이 지나간 선분(시각·좌표)을 서버로 보내고, 서버가 그 시각의 과일 위치로 베었는지 판정해 점수를 준다.
  화면에서는 기다리지 않고 바로 잘리는 모습을 보여 주며(예측), 점수는 서버가 알려 준 값만 쓴다.
- 손 인식은 **각자의 브라우저**에서 돈다(MediaPipe Hand Landmarker). 카메라 영상은 서버로 보내지 않는다.
  - 카메라는 localhost 또는 https 주소에서만 켜진다(Cloudflare 터널 주소는 https 라서 된다).
  - 손 인식 모델(약 8MB)은 게임을 열 때 각 브라우저가 Google 저장소에서 받는다. 미리 받아 서버에서 내려주려면 `server` 폴더에서 `python tools/download_hand_model.py`.
  - 카메라가 없거나 권한을 거부하면 마우스로만 한다.
- 원본에서 빠진 것: 일시정지, 이름 입력·랭킹 저장, 타이틀 화면, 베는 순간의 짧은 멈춤(모두의 시계를 맞추기 위해).
- 수치는 `server/party/games/fruit/config.py` 에 있다(같은 값이 `web/src/games/fruit/sim/rules.js` 에 있고 테스트가 비교한다).

## 가든 디펜스 규칙 (원본과 달라진 점)

- 120초 고정. **각자 자기 정원**에서 **모두 같은 좀비 떼**(같은 시각·같은 레인·같은 종류)를 막고, 점수가 높은 순으로 순위(동점은 공동 순위).
- **사격만** 남겼다: 포탑·무기 해금·아이템·코인·하트(라이프)는 없다. 무기는 권총 하나(탄약 무한, 초당 5발).
- 조작: **손 제스처**(ㄱ자 손 또는 양손 총으로 조준, 검지를 구부리면 발사, 손 높이로 레인 이동) + **키보드 보조**(W/S·↑/↓ 레인 이동, Space 꾹 눌러 사격). 둘을 동시에 쓸 수 있다.
- 좀비를 잡으면 점수(일반 10 · 달리기 15 · 점프 20 · 철모 25 · 보스 500), 2초 안에 이어 잡으면 콤보(4마리마다 +0.5배, 최대 4배).
- **좀비가 집에 닿으면 30점 감점**(탈락 없음, 0점 아래로는 내려가지 않음)하고 콤보가 끊긴다. 보스가 문 앞에 서면 3초마다 계속 감점. *(30점은 임시 값)*
- 웨이브 6개가 정해진 시각에 시작한다(0 · 14 · 31 · 50 · 71 · 94초). **뒤로 갈수록 많고 빠르며, 마지막 웨이브(94초~)는 보스와 함께 권총 한 자루로는 다 막을 수 없게 몰려온다.** *(마릿수·시각은 임시 값 — 포탑이 없어서 원본 마릿수를 그대로 쓸 수 없었다)*
- 보스 체력은 원본 340 → 160(×웨이브 배율)으로 낮췄다. 권총만으로 20초쯤 집중하면 잡을 수 있다. *(임시 값)*
- 판정: 참가자마다 정원 하나를 서버가 60분의 1초 단위로 진행한다. 브라우저는 "있는 레인 / 쏘는 중" 만 보내고, 서버가 보내 주는 좀비·총알 상태를 그린다. 내 캐릭터의 레인 이동만 기다리지 않고 바로 보여 준다.
- 손 인식은 **각자의 브라우저**에서 돈다(과일자르기와 같은 MediaPipe, 공용 모듈 `web/src/shared/HandTracker.js`). 카메라가 없거나 권한을 거부하면 키보드로만 한다.
- 원본에서 빠진 것: 일시정지, 차례대로 하는 방식(지금은 동시에), 타이틀·인원 선택 화면, 처치 순간의 짧은 멈춤(모두의 시계를 맞추기 위해), 점프 좀비의 포탑 뛰어넘기(포탑이 없다).
- 수치는 `server/party/games/garden/config.py` 에 있다(같은 값이 `web/src/games/garden/sim/config.js` 에 있고 테스트가 비교한다).

## 검도 규칙 (원본과 달라진 점)

- **시작 전 30초 연습**: 각자 자기 화면에서 AI(원본 대회 1회전 상대인 공격형 "강철민")와 겨룬다. 원본 코드 그대로 브라우저 안에서만 돌고 **순위에 들어가지 않는다**.
- **리그전**: 모든 사람이 서로 한 번씩 만난다. 한 회전에 짝이 된 사람들이 동시에 경기하고, 인원이 홀수면 한 명이 쉬며 첫 경기를 관전한다(3명 3회전, 4명 3회전, 5명 5회전, 2명은 한 경기).
- **한 경기**: 먼저 **두 판**(한판 2개)을 따면 승리, **60초**. 시간이 끝나면 한 판이라도 앞선 쪽 승리.
  - 동점으로 끝나면 연장전 없이 바로 **심판 판정**(판정받은 타격 내용 + 남은 기세로 깃발)으로 승자를 정한다. *(원본은 연장전 2분 뒤 판정 — 임시로 정한 방식)*
- **조작(키보드만)**: ←→ 이동 · Shift 기합(누르는 동안 충전) · Z 머리 · X 손목 · C 허리 · Space 막기(타격 직전에 누르면 받아치기). 홍은 왼쪽, 백은 오른쪽에 선다(대진 안내에 표시).
- **한판 조건은 원본 그대로**: 간격 + 기합 게이지 45 이상 + 빈틈 + 잔심(친 뒤 0.5초 자세 유지) → 심판 3명 중 2명 이상 깃발. 장외 2회 = 상대 한 판, 코등이 싸움이 길면 "갈려".
- **순위 점수**: 1승 100점 + 딴 한 판마다 10점. *(임시로 정한 값)*
- 판정: 서버가 경기마다 원본과 같은 계산을 60분의 1초 단위로 진행한다(원본 선수·판정 코드를 Python 으로 옮겼고, 테스트가 원본 JS 와 결과를 비교한다). 브라우저는 누르고 있는 키와 새로 누른 키만 보낸다.
- 화면은 원본 시합 장면(무대·선수·심판·HUD·효과·소리)을 그대로 쓴다. 글자는 원본처럼 갈무리 비트맵을 직접 찍으며, 참가자 이름에 어떤 글자가 와도 되도록 한글 음절 전체를 담았다(`pk/data/font_data.js`, 약 1.4MB).
- 원본에서 빠진 것: 도장 수련(튜토리얼), 이야기·대회 진행, 일시정지, 디버그 화면, 찌름(원본에서도 미해금).
- 걸리는 시간: 연습 30초 + 회전마다 1~1.5분쯤 (3명 약 5분, 5명 약 7~8분).
- 수치는 `server/party/games/kendo/config.py` 에 있다(선수·판정 값은 원본 `pk/config.js` 와 같고 테스트가 비교한다).

## 레이싱 규칙 (원본과 달라진 점)

- 모두 같은 트랙을 동시에 달려 **3바퀴를 먼저 도는 순서**로 순위를 정한다. AI 차는 없고(사람끼리만), **차끼리는 부딪히지 않고 겹쳐 지나간다.**
- **1등이 들어오면 그때부터 30초** 동안 나머지도 계속 달린다. 그 안에 못 들어온 사람은 달린 거리 순으로 뒤 순위를 받는다.
- **점수는 순위별로 다르다**: 1등 100 · 2등 70 · 3등 50 · 4등 30 · 5등 10. *(임시 값)*
- **조작은 카메라 동작**: 두 손을 핸들처럼 들고 기울이면 방향, **두 손을 카메라 쪽으로 밀면 가속**, 당기면 감속·후진, 핸들을 끝까지 꺾으면 드리프트.
  - 손 크기의 기준은 처음 두 손이 보였을 때 잠깐 재서 정한다(설명 화면 동안). `R` 로 다시 잴 수 있고, 방향이 반대로 느껴지면 `I` 로 뒤집는다.
  - **카메라를 쓸 수 없는 사람만 키보드**(↑ 가속 · ↓ 감속/후진 · ←→ 방향 · Space 드리프트)로 조종한다. 카메라가 켜진 사람은 키보드가 먹지 않는다.
  - 손 인식은 각자의 브라우저에서 돈다(공용 `web/src/shared/HandTracker.js`). 원본은 몸 자세(포즈) 인식이었으나, 손이 앞뒤로 움직인 정도를 재야 해서 손 인식으로 바꿨다.
- **잔디는 보이지 않는 벽**이다: 도로 밖으로 나가려 하면 가장자리에서 막히고 속도가 줄어든다(원본은 잔디에서 느려지기만 했다).
- **타이어 자국은 2초 뒤 사라진다**(원본은 계속 남았다).
- **맵을 복잡하게 바꿨다**: 원본의 둥근 사각형 대신 헤어핀·S자가 있는 서킷(한 바퀴 약 24초). 맵은 화면보다 크고 화면이 내 차를 따라가며, 오른쪽 위에 미니맵이 있다. *(맵 모양은 임시로 그린 것 — `config.py` 의 `TRACK.POINTS` 점들을 옮기면 바뀐다)*
- **픽셀 아트**: 트랙·나무·차(32방향)를 코드로 그린다(320×180).
- 차의 움직임(가속·접지력·조향·드리프트)은 원본 식 그대로이고 화면 크기에 맞춰 속도만 줄였다.
- 판정: 서버가 모든 차를 60분의 1초 단위로 움직인다. 브라우저는 조향·가속·드리프트 값만 보낸다. 내 차는 같은 식으로 바로 움직여 보이되 서버 위치 쪽으로 계속 끌어당긴다.
- 아무도 못 들어와도 3분이 지나면 끝난다. *(임시 값)*
- 수치는 `server/party/games/racing/config.py` 에 있다(같은 값이 `web/src/games/racing/sim/config.js` 에 있고 테스트가 비교한다).

| `fight` | 매직 파이트 나이트 | 1:1 리그전(라운드마다 동시에) | 2~5분 | ←→ 이동, Space 펀치, ↓ 가드 |
| `pingpong` | 잭팟 탁구왕 | 1:1 리그전(라운드마다 동시에) | 2.5~8분 | ←→ 후진/전진, Space 치기 |

- 리그전 두 게임(`fight`, `pingpong`)은 5명이면 5라운드라 오래 걸린다.
- 모든 게임에서 `M` 은 소리 끄기/켜기.
- 서버 판정 코드는 `server/party/games/<id>/`, 화면은 `web/src/games/<id>/` (원본 그림 · 소리 코드를 ES 모듈로 옮겨 씀), 시험용 진행기는 `web/src/games/<id>/sim/Sim.js`.

### AI — 서버의 Gemini 만 쓴다 (`server/party/services/caster.py`)

`GEMINI_API_KEY` 가 있으면 켜지고, 없으면 준비된 기본 대사로 똑같이 진행된다(위 "Gemini 문제 생성 켜기"와 같은 방법).
Gemini 는 답하는 데 1~3초가 걸리므로 게임 진행 중에는 부르지 않고, **미리 스레드에서 받아 두고 온 것만 쓴다.**

| 쓰임 | 언제 요청하나 | 어떻게 보이나 |
|---|---|---|
| AI 해설 (10개 모두) | 게임이 시작될 때 한 번 — 상황 8~10가지의 대사 묶음을 JSON 스키마로 받음 (`LineBook`) | 해설자 · 마법사 · 호랑대장 · 꽥대장의 자막/말풍선. Gemini 가 쓴 줄에는 "AI" 표시 |
| AI 총평 (10개 모두) | 결과가 정해질 때 한 번 (`ask_verdict`) | 최종 순위 화면의 "AI 총평" 세 줄 |
| 그림 감상평 (`sigil`) | 라운드마다 한 번 — 모든 참가자의 그림(PNG)을 글과 함께 한 요청에 담음(멀티모달) | 갤러리에서 "무엇처럼 보이는지" + 마법사의 한마디. **점수는 규칙 계산, 감상평만 Gemini** |
| 수업 계획 (`sneaky`) | 게임이 시작될 때 한 번 — 교수님이 언제 · 어떻게 돌아볼지 10~14단계 | 계획이 쓰이는 동안 "AI 수업 계획" 표시. 값은 원본 범위로 자르고, 늦거나 틀리면 원본 규칙대로 |

한 판에 Gemini 요청은 2번(해설 묶음 + 총평)이고, `sigil` 은 5번, `sneaky` 는 3번이다.
`services/gemini.py` 의 `generate_json` 에 `images`(사진 부분)와 `system`(시스템 프롬프트) 인자를 추가했다.

### 테스트할 때 (Windows)

서버 테스트는 한글 출력 때문에 UTF-8 모드로 돌린다: PowerShell 에서 `$env:PYTHONUTF8='1'` 을 먼저 실행한 뒤 `python -m pytest -q`.
새 게임의 시험용 진행기는 `web` 폴더에서 `node tests/<id>-sim.mjs` 로 한 판씩 돌려 볼 수 있다.

## 보드게임 (RE:ROLL 파티) — 방 코드 · 주사위 보드 · 미니게임

feature/KMJ 브랜치의 보드게임 화면(`board/`)을 이 Python 서버에서 함께 내보낸다. 서버를 켜고 `http://localhost:8000/party/` 를 연다.

- 흐름: 메인 화면(이름 입력) → 방 만들기 / 방 번호 4자리로 참가 → 대기실(빈 자리는 CPU) → 보드(모두 동시에 주사위 선택 → 이동 → 칸 효과) → **턴마다 미니게임** → 순위에 따라 특수 주사위 보상 → 결승에 먼저 닿거나 정해진 턴이 끝나면 최종 순위.
- 보드 진행(방 · 주사위 23종 · 칸 효과 · 보상)은 원래 Node 서버(`docs/kmj-original/party.js`)에 있던 것을 `server/party/board/` 로 옮겼다. 통신 형식은 그대로라 화면 코드는 미니게임을 여는 부분만 바뀌었다. 자세한 내용은 `docs/board-server.md`.
- **미니게임 차례**: 서버가 그 방 사람들만 모이는 미니게임 허브를 만들고(`server/party/board_bridge.py`), 등록된 미니게임 20개 중 하나를 직접 시작한다. 보드 화면은 미니게임 화면(`/`)을 내장 모드(`?embed=1&room=…`)로 열 뿐이고, **순위는 서버가 판정한 결과**를 그대로 쓴다(원래는 각자 브라우저가 보낸 점수를 믿었다).
- 사람이 1명뿐이면 서버 판정 게임(2명 이상)을 할 수 없어서, 시험용 봇과 한 판 하고 그 점수를 보낸다(`?embed=1&local=3&game=…`).
- CPU 자리의 미니게임 점수는 원래 규칙대로 사람 평균의 50~115% 에서 무작위로 정한다.
- 아직 없는 것: 스토리보드의 인트로 영상, 캐릭터 고르기(자리 순서대로 곰 · 고양이 · 오리 · 호랑이 · 시바 고정), 보스전, 굿/배드 엔딩. 원래 화면에도 없던 부분이다.
- `/` 는 예전처럼 미니게임만 따로 시험하는 대기실이다.
